# 上下文感知门控研究——消除 GatedFusionMLP 扩容副作用（2026-07-29）

> 研究子代理报告。问题：扩容门控对"注入知识块"和"自然 gist"一并开权重，干扰滑窗 L0 精确召回（0.688→0.250）。目标：门控区分"注入条目"vs"自然 gist"，保注入召回 + 恢复纯文本精确召回。
> 标注约定：[已核实]=真实出现在 tavily 搜索结果中；[存疑]=编号/细节未经二次确认；[外推]=我们的推断非文献直接结论。

---

## 一、检索结果（按主题）

### 主题1 稀疏/检索注意力的分支门控（最贴合我们的三分支结构）

- **NSA（Native Sparse Attention）** arXiv:2502.11089 [已核实]
  - 核心：与我们的三级栈同构——滑窗 + 压缩(cmp) + 选择(slc) 三分支，分支输出经**学习门控**聚合。
  - **关键结论（直接对症）**：§2.3.3 指出"局部模式适应更快、会主导学习过程，使压缩/选择分支学不到特征"，因此**显式设立独立滑窗分支**处理局部上下文，让其他分支不被局部"抄近路"。启示：分支**隔离**是防止压缩分支干扰局部精确分支的第一道防线。
  - 后续工作（arXiv:2511.00819 [已核实]）实证：滑窗主导常识推理、选择分支主导检索、**"滑窗+选择并用会削弱选择分支的检索能力"**——分支间干扰是真实存在的，与我们的副作用同因。

- **TokenMem** arXiv:2607.22625 [已核实]（本问题最相关）
  - 核心：冻结 LLM + 每层**零初始化门控**的交叉注意力适配器（改自 DecoupledRAG），把检索知识经**独立通道**注入。
  - **关键设计**：复用主干 WQ/WK/WV 投影；交叉注意力结果经 LoRA 式低秩变换 `Wβ=α·AβBβ`，**Bβ 零初始化 ⇒ 训练起点 Wβ=0**（恒等，不破坏 backbone）；冻结主干保证 original utility 数学上不变。
  - **对我们的启示（强）**：注入知识走**独立的、门控初始为零的通道**，与原上下文路径**解耦**——正是"注入条目 vs 自然 gist 分离"的工业级范式。其"设置 g≡0 即精确恢复未适配 backbone"与我们 GatedFusionMLP 恒等初始化（fc2=0 保 g=1/3）的设计哲学一致。

- **DecoupledRAG**（被 TokenMem/多篇引用 [已核实存在]）
  - 核心：检索知识**不复用自注意力路径**（避免与 in-context 冲突），改走独立交叉注意力 + 门控。指出 RAG/REALM 把检索文档"路由进同一自注意力层会制造冲突"——正是我们 gist 与注入混在同一 HCA 门控通道的病灶。

### 主题2 知识注入/编辑的共存防干扰门控

- **MEGa** arXiv:2504.21239 [已核实]
  - 核心：每条记忆存一组**专属门控 LoRA 权重**；推理时门控用 query embedding 匹配 memory embedding，**加权求和只激活相关 adapter**，其余不激活——用"查询-记忆匹配"实现选择性激活，缓解灾难性遗忘。
  - 启示：门控输入应包含**条目侧特征**（而非仅 query），让门控按"条目内容/来源"差异化加权——支持"条件/内容感知门控"路线。
  - 注意：其实验也显示相关性高的记忆间仍有"门控选择干扰"，说明纯内容匹配并不完美，可能需要更显式的来源信号。

- 知识编辑谱系（MEMIT arXiv:2210.07229 / SERAC / GRACE / WISE arXiv:2405.14768，均[已核实存在]）
  - SERAC/DEFER 的 **scope classifier**：一个网络 g 判断"信任 LLM 原预测 vs 信任新编辑预测"——**按输入决定走新记忆还是旧参数**的二选一仲裁。这是"注入 vs 原有"分离门控的直接先例。

### 主题3 稀疏/硬门控（让门控"非此即彼"）

- **L0 正则 / hard-concrete 门** [已核实方法存在，源自 Louizos et al. 2017 经典工作；检索命中 arXiv:2409.03489 应用文]
  - 核心：binary concrete 分布 + hard-sigmoid 拉伸，学出**恰为 0 的可微二值门**；优化目标含"门激活概率"项，鼓励关闭。
  - 启示：给门控加 L0 稀疏正则，可让它对 gist 条目学到**精确 0**（而非小权重），从根上消除"对 gist 也开一点"的泄漏。

- **Gumbel-Sigmoid / Gumbel-Softmax + ST estimator** [已核实方法存在；命中 arXiv:2503.13304、arXiv:2506.07500]
  - 核心：Gumbel 噪声 + sigmoid 温度退火，前向近二值、反向可微；温度↓从探索转向**硬选择**。
  - 启示：把 GatedFusionMLP 的 sigmoid 换成 Gumbel-sigmoid（训练带噪、推理取硬阈值），迫使门控对"注入/gist"做出离散取舍而非均匀开权重。

### 主题4 上下文依赖/内容感知路由

- MoE 路由研究（综述性命中 [已核实]）："Routing responds to Context"(2024)、Graph of Tokens(Nguyen 2025) 等指出——纯 token-ID 路由是"上下文无关特化"，需让路由**感知 token 间关系/上下文**。启示：门控输入若只有 q，容易学成"对某类条目一律开权重"；需注入区分性特征。

### 主题5 来源标记 / 命名空间感知

- **P-RAG / Parametric RAG** arXiv:2501.15915、arXiv:2510.12668 [已核实]
  - 核心：区分 in-context 注入（token 级）与 parametric 注入（参数级）两条通路，**可并行结合**；明确"token 注入只影响注意力 KV、参数注入影响 FFN 权重"的载体边界。与我们 Block Spec 的 `factual_recall`/载体边界标注一致。
- 直接"source embedding flag"的独立论文本轮未检到强命中 [诚实标注]；但 TokenMem/DecoupledRAG 的"独立通道"本质上就是一种**结构性来源标记**（用架构而非 embedding 区分来源）。

## 二、候选解决方案

### 方案A：解耦双通道门控（注入条目走独立门控通道）★推荐
- **原理**：借 TokenMem/DecoupledRAG。把 HCA 分支内部再分两路——"自然 gist 条目"走原门控通道（保持原有低权重/行为不变），"运行时注入的知识块条目"走**独立的、初始为零的门控通道**。两路各自 sigmoid 门控，最后相加/拼接。
- **如何应用到 GatedFusionMLP**：现状 `g=sigmoid(MLP(q))` 输出 3 维（L0/CSA/HCA）。改为：HCA 这一路拆成 `g_hca_natural`（沿用原 MLP，初始化保持现值→对 gist 维持原权重）与 `g_hca_inject`（新增小 MLP，fc2 零初始化→起点 g≈0，仅对注入条目激活）。前向对自然条目只用 `g_hca_natural`，对注入条目用 `g_hca_inject`。等价于把"注入 vs gist"的判别从"让 MLP 自己学"变成"架构层面硬分离"。
- **能否消除副作用**：**能，且最彻底**。自然 gist 通路完全不经过被召回训练改动的权重 ⇒ 纯文本精确召回天然恢复；注入通路独立优化 ⇒ 召回能力保留。文献支撑强（TokenMem 零初始化独立通道 [已核实]）。**[直接文献支撑]**
- **来源标记**：不需要 embedding 级标记——用**结构（条目挂载位置/通道索引）**区分，这是最可靠的"命名空间"。与我们 BlockStore 的五元组 namespace 天然对应。
- **复杂度**：中。需改 tri_attention_gated 的注入挂载点，按条目 namespace 路由到不同门控头；不动主干、不动 gist 通路。恒等初始化沿用 fc1 随机破对称 + fc2=0 的经验（见 gated-fusion-mlp 记忆）。

### 方案B：条件/内容感知门控（门控输入含条目来源特征）
- **原理**：借 MEGa（query-memory 匹配）+ MoE 上下文路由。让门控不只看 q，还看**每条目的来源标记/内容特征**，输出对该条目的差异化权重。
- **如何应用**：给 HCA 的每个 KV 条目附加一个可学习**source embedding**（注入块=1 个向量、自然 gist=另 1 个向量，或用 BlockStore namespace id 查表）；门控改为 `g_i=sigmoid(MLP([q; src_i]))`，对条目 i 逐条打分。训练时注入条目标"开"、gist 条目标"关/保持"。
- **能否消除副作用**：**大概率能，但依赖训练信号充分**。门控有了区分依据，理论上可学到按来源分流；但 MEGa 实验提示高相关条目仍有串扰，若来源特征不够显著或训练数据里 gist/注入比例失衡，可能仍有泄漏。**[部分文献支撑+外推]**
- **复杂度**：中高。需改注意力内核让门控能读到每条目的 source 标记（当前门控只在 query 侧），实现与 Kernel 挂点耦合；source embedding 需随 BlockStore 注册。

### 方案C：稀疏/硬门控 + 来源正则（训练期约束）
- **原理**：借 L0/hard-concrete + Gumbel-sigmoid + SERAC scope 仲裁。保持现有单门控结构，但 (a) 把 sigmoid 换成 Gumbel-sigmoid 逼门控做硬取舍；(b) 加**来源条件正则**——对 gist 条目加"门控权重趋近原值/趋 0"的 L1/L0 正则，对注入条目加"门控权重趋 1"的 BCE 损失。
- **如何应用**：训练召回时，损失 = 召回 CE + λ1·‖g(gist)‖₀（稀疏化，鼓励对 gist 关）+ λ2·BCE(g(inject), 1)（鼓励对注入开）。推理可对 g 取硬阈值。
- **能否消除副作用**：**部分能**。正则直接压制对 gist 的开权重，理论上能恢复精确召回；但属"软约束"，权重权衡 λ 需调，且单一门控同时服务两类目标存在梯度拉扯，不如方案A的硬分离干净。**[方法有文献支撑，组合应用为外推]**
- **复杂度**：低-中。只改训练脚本（加正则项）与门控激活函数，不动架构；最适合快速验证。

## 三、推荐

**首选方案A（解耦双通道门控）**，理由：
1. 文献支撑最直接（TokenMem arXiv:2607.22625 的"独立零初始化门控通道 + 冻结/不变原通路"与我们恒等初始化哲学同源）；
2. 从架构上保证"自然 gist 通路零改动"→ 纯文本精确召回必然恢复，副作用**结构性消除**而非靠调参压制；
3. 用 BlockStore namespace 做来源路由，无需新增 embedding 学习，契合项目"namespace 五元组 fail-closed"既有红线；
4. 复杂度可控，只动注入挂载点，不碰主干与 gist 通路，红线合规。

**落地顺序建议**：先做**方案C**（成本最低，1-2 天可验证"来源条件正则能否恢复精确召回"），作为对照基线；再上**方案A**作为正式解。方案B 若未来需要"同一条目按内容细粒度分流"再考虑（当前二分来源用结构化路由已够）。

## 四、关键回答（对应任务提问）
- **是否需来源标记**：是，但优先用**结构化来源路由**（按条目挂载通道/namespace）而非学习的 source embedding——更可靠、符合既有 namespace 红线。方案B 才需要 embedding 级标记。
- **可否解耦门控**：可以且推荐（方案A），有 TokenMem/DecoupledRAG 直接先例。
- **可否条件门控**：可以（方案B），MEGa 提供 query-memory 匹配先例，但有串扰风险。
- **可否正则**：可以（方案C），L0/Gumbel 稀疏门 + 来源条件 BCE，成本最低，适合作对照。

## 五、诚实标注汇总
- 直接文献支撑：方案A（TokenMem/DecoupledRAG 独立零初始化通道）；稀疏门方法本身（L0/Gumbel）。
- 外推：方案A 具体到"三分支 HCA 内再分双通道"是我们的适配（文献是"检索通路 vs 自注意力通路"的二分，我们迁移到"HCA 内 gist vs 注入"的二分）；方案B 的来源 embedding 细粒度分流；方案C 的正则组合。
- 未检到：专门用"source embedding flag 区分注入 vs 原上下文"的独立强论文——该思路更多以"独立通道/参数级 vs token级"的结构性形式出现。
