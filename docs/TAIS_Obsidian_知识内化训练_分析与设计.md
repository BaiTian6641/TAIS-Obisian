## 1. 问题分解：知识内化的两个层次

用户场景拆成两类：

| 场景 | 触发 | 关键要求 |
|---|---|---|
| **A. 求知后学习** | 模型主动问"不知道"（求知分支 AskQuestion）→ 用户回答 → 模型学到 | 学到的知识**实时可用**（同一对话后续即可用） |
| **B. 知识链条内化** | 用户直接给出一套知识链条 → 模型**退联检验**（验证与既有知识的一致性）→ 学到 | 检验真伪/一致性 + 实时可用 |

**核心矛盾**：实时可用（快，运行时）vs 经得起验证（慢，交叉验证+睡眠固化）。解法是**双速通道**（CLS 双系统，已落设计）：

```
运行时（快，秒级）：新证据 → 交叉验证 → 知识块（steering 式有界写入，W1–W2 零梯度）
  → 实时可用（推理循环 HRL 检索即可命中，注入参与推理）
睡眠期（慢，离线）：知识块 → CA1 门（先验一致性调速）→ 间隔提取练习 → 固化入主干
  （W3+/W4，Muon 同优化器，谱修剪）→ 长期记忆
```

**"实时可用"的实现**（已落地部件）：新知识写入 BlockStore 后，推理循环的 HRL 检索（route_candidates + CA3 PPR 联想）即可命中 → kernel.inject 注入（KV 拼接/记忆层 delta/向量 steering）→ **同一对话后续立即可用**，无需等睡眠固化。这是 token 寻址载体（KV/记忆层）的事实召回能力（对齐"载体能力边界"红线）。

## 2. 知识内化的训练目标（如何训练"学到"这个行为）

部件已备（求知分支/执行器/交叉验证/知识块/睡眠固化），但**模型不会自动学会"在用户给知识时正确内化"**——需显式训练。三个训练目标：

### 2.1 内化行为训练（In-Context Learning to Learn）

**目标**：给定"用户给知识 → 后续相关问题"的样本，训练模型**真的用上**新知识（而非忽略或凭先验答）。

**方法 [已确立+推测]**：
- **教学式 SFT**：构造样本 `{知识链条 K, 问题 Q, 答案 A(K)}`，其中 A 必须**依赖 K 才能答对**（用先验知识答不出）。训练信号：答对需要 K 的问题 → 强化"用新知识"。这正是**知识内化**的直接监督。
  - 数据源（数据集选型文档）：cosmopedia 教科书、finemath 数学知识链、教学式/解释式数据。
  - 关键：**Q 必须 K-依赖**（构造时验证——去掉 K 后模型答错，加上 K 后答对），否则模型学会"忽略 K 凭先验答"。
- **退联检验训练**（场景 B）：用户给知识链条，模型须**先验证再内化**——训练样本含"一致知识（应内化）vs 矛盾/错误知识（应拒/标注分歧）"。奖励正确区分：一致→内化可用，矛盾→Decline/标注分歧（对齐诚实降级+冲突不静默覆盖红线）。

### 2.2 元认知门控训练（知道何时该内化）

**目标**：模型学会"何时该学（用户给了我不知道的新知识）vs 何时不该学（我已知道/用户在误导）"。

**方法 [已确立]**：
- **KAL P(IK) 三态监督**：对齐 KAL 真值锚——用户给的新知识若是模型空白（P(IK) 低）→ 应学；若模型已知（P(IK) 高）→ 不必重复学；若是错误信息（与先验冲突且不可信）→ 应拒。
  - 数据源：squad_v2（不可答）、SelfAware（不可答对照）、UA-Bench（数据不确定 vs 模型不确定）。
  - **防误导**：用户给的"知识"可能是错的——模型须用交叉验证（CrossVerifier）判真伪，不可盲目内化（对齐"绝不裸自我修正"红线，arXiv:2310.01798）。

### 2.3 实时可用性训练（学到即可检索）

**目标**：内化后的知识块**能被 HRL 检索命中并正确注入**（实时可用的技术前提）。

**方法 [推测/独创]**：
- **检索-内化联合训练**：内化样本同时训练 HRL indexer——新写入的知识块应被后续 query 的 route_candidates 命中（检索监督），注入后答对（端到端监督）。
- **梯度隔离红线**：检索/注入辅助损失只进 indexer/路由器，禁污染主干（MoE-RL 红线）。

## 3. 训练管线（三阶段，对齐已有部件）

```
阶段 1（SFT 教行为，离线）：
  教学式 SFT（K-依赖问答）+ 退联检验（一致/矛盾区分）+ KAL P(IK) 监督
  → 模型学会"给新知识→验证→内化→实时可用"的行为模式
  → 数据：cosmopedia/finemath（教学）+ squad_v2/SelfAware（不可答）+ 合成 K-依赖样本

阶段 2（运行时闭环，在线 pilot）：
  推理循环 + 求知分支 + 求知执行器（CrossVerifier 验证 + KnowledgeBlockWriter 写入）
  → 真实对话中：用户给知识 → 验证 → 写知识块 → HRL 命中 → 注入 → 实时可用
  → W0 日志记录内化轨迹（资格迹）

阶段 3（睡眠固化，离线）：
  W0 日志 → CA1 门（先验一致性调速：一致快/冲突慢+校验）→ 间隔提取练习 → 固化入主干
  （Muon 同优化器 + 谱修剪 + 三元奖励 RL：答对+1/幻觉−1/abstain 0~0.3）
  → 长期记忆 + 防止错误固化（累积不覆盖 + 验证门）
```

## 4. 关键风险与防御

1. **凭先验答而非用新知识**（最大风险）：模型可能忽略用户给的知识，凭预训练先验答。
   - 防御：K-依赖样本构造（去掉 K 答错）+ 检索监督（强制命中新块）+ 说-做一致性审计（CoT 投影层：说的推理须用到新块）。
2. **盲目内化错误知识**（用户误导/投毒）：模型把错误"知识"当真内化。
   - 防御：CrossVerifier 外部验证（多源+先验一致性+冲突检测）+ 信任度加权（弱证据弱更新）+ 冲突保留双方标分歧 + 睡眠期验证门（校验集回归）。**绝不裸自我修正**。
3. **实时知识与固化知识不一致**：运行时写入的块未经睡眠固化，可能与固化主干冲突。
   - 防御：CA1 门按先验一致性调速（一致快固化/冲突慢+校验）；累积不覆盖（版本化）；markdown 源代码形态=最终审计/回滚依据。
4. **知识内化的泛化**：教学式 SFT 可能过拟合特定知识格式。
   - 防御：多样化数据（句式/领域/否定/疑问/contrast-pair，对齐 diverse_truth_data 经验）；OOD 评估（kal_probe 模板）。

## 6. 诚实边界

1. **"实时可用"的知识是运行时块（未固化）**：与睡眠固化入主干的知识在持久性/容量上不同——运行时块受 BlockStore 容量/检索质量限制，长期依赖睡眠固化。
2. **退联检验的"验证"是概率的**：CrossVerifier 语义相似度近似非真值判定（pilot），正式需多源检索+外部锚——模型可能误信貌似一致的错误知识。
3. **K-依赖样本构造难**：保证"去掉 K 答错"需精心设计（否则监督信号弱）；大规模构造需自动化管线。
4. **内化-检索-注入端到端训练未验证**：检索监督+注入监督的联合训练是 [推测/独创]，pilot 需消融各环节贡献。
5. **用户给知识的格式多样**（自然语言/代码/公式/链条）：内化的统一表征（知识块载荷形式）需按载体能力边界标注（token 寻址可事实召回 vs 向量只能 steer）。
