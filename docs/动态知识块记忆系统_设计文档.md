## 0. 文档说明

本文档记录一个仍在探索中的架构设想：为大语言模型提供一个**可动态接入外部权重的"接口"**，使模型在推理过程中能够像操作系统访问虚拟内存一样，按需调用、换入、换出以"知识块"为单位组织的知识与经验。文档的目标是：

1. 固定讨论中形成的共识与设计决策；
2. 标注每个设计点对应的已有研究证据（可行性验证）；
3. 列出尚未解决的开放问题，作为后续讨论与实验的锚点。

本文档不预设任何实现已被验证；所有"证据"均为相邻领域的支持性工作，组合后的完整系统尚无先例。

## 1. 愿景与动机

### 1.1 要解决的问题

当前 LLM 智能体的"记忆"主流实现是**外挂文本**（markdown 文件、向量数据库、RAG）。这带来三个根本局限：

1. **知识不以模型内生形式存在**：每次使用都要重新以文本形式读入、重新"理解"，经验无法真正进入模型的推理过程；
2. **模型不能持续学习**：权重 frozen，新经验只能堆积在上下文里，受窗口长度限制；
3. **模型对自己的知识状态无感知**：遇到知识空白时倾向于盲目猜测（幻觉），而非主动"回想"或获取。

### 1.2 核心设想

提供一个**定制化接口**，作为动态接入模型权重的通道，类比计算机体系结构中的**页表地址转换**：

- 模型在思考/推理过程中向该接口发出请求；
- 接口连接一个外部路由软件与一众额外权重（知识块），进行二次路由；
- 被路由到的知识块返回**双通道载荷**：文本（推理可用的内容）与额外权重（对模型内部表示的映射/调制）；
- 知识块有层级存储（显存-内存-闪存），动态加载与卸载，路由器可学习、与模型共同进化；
- 模型检测到自身知识/经验空白时，主动发起"回想"，而非盲目猜测；
- 知识块分**纯知识类**与**人格类**，实现对智能体的深度集成；
- 模型完全卸载后重新加载时，知识块按特定顺序恢复（参考全身麻醉后意识恢复的研究）。

## 2. 总体架构：模型权重的"虚拟内存系统"

### 2.1 体系结构类比

本架构与经典计算机体系结构的映射关系（这是全文的核心隐喻，也是设计语言的来源）：

| 计算机体系结构 | 本架构 | 已有相邻工作 |
|---|---|---|
| 虚拟地址 | 模型推理中产生的需求向量（hidden state / routing query） | MoE gating 输入 |
| 页表 / MMU | 接口层：将需求翻译为知识块地址 | PEER 的可学习 product-key 索引（arXiv:2407.04153） |
| 页（page） | 知识块（统一命名的最小记忆单元） | S-LoRA 的 adapter 分页（arXiv:2311.03285） |
| TLB | GPU 常驻的热知识块缓存 | MoE 推理系统中的 expert cache（文献中直接出现"组相联缓存"表述） |
| 缺页中断（page fault） | 路由 miss → 异步取块 / 降级执行 | PreScope 异步 I/O + CPU 回退（arXiv:2602.05030） |
| 预取（prefetch） | 预测下一段思考将访问的块并提前挂载 | PreScope / fMoE 的专家预取 |
| Swap / 换出 | 冷块换出至 DRAM / NVMe | LMCache、MTDS 的三级 KV 层级 |
| 按需分页（demand paging） | 用到才加载 | LMCache 的 KV 提取/重载接口（arXiv:2510.09665） |
| Bootloader | 冷启动时的最小自我加载序列 | 麻醉苏醒研究的启发（见 §5） |

### 2.2 组件总览

```
┌────────────────────────────────────────────────────┐
│  基础模型（主干权重 frozen 或慢速更新）               │
│   ├─ 接口调用点：推理中发出 routing query            │
│   ├─ 注入点：接收权重载荷（LoRA/KV/steering vector） │
│   └─ 信号导出点：hidden state / 输出分布 / 反思 token │
└──────────────┬─────────────────────────────────────┘
               │ 接口 ABI（§9）
┌──────────────▼─────────────────────────────────────┐
│  接口层（"MMU"）                                    │
│   ├─ 页表：知识块注册表（route_key → 物理位置+元数据）│
│   ├─ 路由器（可学习）：精确匹配 + 联想采样           │
│   ├─ 预测器：分支预测式预取                          │
│   └─ 缺页处理：超时 / 降级 / 回退                    │
└──────┬───────────────┬───────────────┬─────────────┘
       ▼               ▼               ▼
  L0: VRAM        L1: DRAM        L2: NVMe/远端
 （工作记忆）    （短期记忆）     （长期记忆）
               │
┌──────────────▼─────────────────────────────────────┐
│  后台进程                                          │
│   ├─ 记录器：在线捕获推理信号（空白事件/纠正/轨迹）    │
│   ├─ 编译器：睡眠时间将文本经验固化为内部表示          │
│   └─ 仲裁器：冲突解决、版本管理、淘汰                 │
└────────────────────────────────────────────────────┘
```

## 3. 知识块规范（Block Spec v0.1）

知识块是系统的"指令集架构"（ISA）：规范定好后，页表、路由器、编译器、缺页处理各自迭代都不会跑偏。

### 3.1 设计原则：双形态

每个知识块同时保存两种形态：

- **源代码形态（markdown / 结构化文本）**：人类可读、可编辑、可版本管理、可审计；是 ground truth；
- **编译产物形态（内部表示）**：模型可直接条件化使用，插入即生效、无需重新"理解"；是可失效的缓存，丢失后从源代码重新编译。

编译在**睡眠时间**（离线）进行，不在线执行。

### 3.2 块类型分型

"知道一个事实"和"会一种做法"在模型内部的物理载体不同（Knowledge Neurons 研究表明事实性知识存储于 FFN 的 key-value 结构中，arXiv:2104.08696），因此知识块按类型使用不同载荷：

| 类型 | 内容 | 编译产物载体 | 体系结构类比 |
|---|---|---|---|
| 陈述性块 | 事实、领域知识、对话结论 | 压缩 KV prefix / memory slots | 数据段 |
| 程序性块 | 推理习惯、某类任务的解法套路 | 从成功推理轨迹蒸馏的 LoRA | 代码段 |
| 元数据块 | "我不擅长什么"、"哪里常错" | 反思触发条件 + 检索路由条目 | 异常处理表 |
| 人格块 | 价值观、性格特质、行为边界 | persona vector 组 + 人格摘要 | 固件 / bootloader 参数 |

### 3.3 字段规范（草案）

```
KnowledgeBlock {
  id:             UUID
  type:           DECLARATIVE | PROCEDURAL | META | PERSONA
  source_text:    markdown 原文（源代码形态）
  compiled:       { kind: KV_PREFIX | LORA | STEERING_VEC | SLOT_TOKENS,
                    payload_ref: 存储位置与格式版本 }
  route_key:      检索用 embedding（多粒度：块级 + 段级）
  graph_links:    [{ target_id, edge_type: SIMILAR | CO_USED | CAUSAL | CONTRADICTS }]
  confidence:     [0,1]，来源可靠性
  version:        单调递增；CONTRADICTS 边连接冲突版本
  created_at / updated_at / last_used_at
  usage_count:    调用次数（固化与淘汰的依据）
  ttl:            存活策略
  priority:       冷启动加载优先级（§5）
  signature:      防篡改签名（防记忆投毒）
}
```

### 3.4 生命周期状态机

```
draft（在线捕获）
  → validated（验证/用户确认）
  → compiled（睡眠时间编译出内部表示）
  → resident（被路由调用，usage_count 增长）
  → demoted（长期未用，逐层下沉 L0→L1→L2）
  → archived / forgotten（淘汰，仅留源代码或彻底删除）
```

## 4. 存储层级与动态调度

### 4.1 层级映射

| 层级 | 物理介质 | 记忆类比 | 内容 | 延迟量级 |
|---|---|---|---|---|
| L0 | GPU VRAM (HBM) | 工作记忆 | 当前思考段所需块、人格块、路由器本身 | ~ns–μs |
| L1 | CPU DRAM | 短期记忆 | 近期高频块、预取候选 | ~100ns |
| L2 | 本地 NVMe | 长期记忆 | 全部编译产物 | ~100μs |
| L3 | 远端/对象存储 | 档案记忆 | 源代码形态全集、冷归档 | ms+ |

**可行性证据**：

- LMCache（arXiv:2510.09665）已实现 KV cache 在"CPU 内存—本地磁盘—远端—Redis"层级间的提取、存储与按需重载，并提供标准化 connector 接口与推理引擎解耦；生产级 L0/L1/L2 分层（GPU 前缀缓存、共享主机缓存、分布式 Mooncake 池）已在 H100 集群上把 TTFT 从 3.98s 降到 0.29s；
- MTDS（Springer, 2026）在资源受限设备上实现了 KV cache 的三层动态存储与自适应淘汰，并证明"选择性加载 vs 重算"存在可按 token 数分类的最优策略区间；
- 这些工作处理的是 KV cache，本设计把同样的层级思想推广到**权重与编译产物**——粒度更大、换入换出频率更低，工程压力反而更小。

### 4.2 动态加载与卸载策略

- **淘汰依据**：LRU × 重要性 × 置信度加权（长期记忆"缓慢扫入内存然后缓存"即 L1 作为 L2 的读缓存）；
- **粒度**：不按 token 路由（带宽不可行），按**思考段**（几十到几百 token）路由与预取；
- **预取**：预测器根据当前 hidden state 提前 1–2 个思考段预测将访问的页（类比分支预测器；PreScope 已在 MoE 语境验证层间预测可行）；
- **缺页降级**：超时 → 使用次优块 / 退回文本 RAG / 明确声明"该部分记忆暂不可用"。

## 5. 冷启动与"苏醒序列"

### 5.1 神经科学依据

用户提出的关键问题：模型完全卸载再重载后，知识块不应全部同时加载，而应**有顺序地恢复**——类似于全身麻醉后意识的恢复过程。相关研究发现：

- **Mashour 等（eLife, 2021, PMC8163502）**：60 名健康志愿者、3 小时深度全身麻醉后的多中心研究证实——
  1. 认知重构是一个**随时间展开的过程**，而非瞬间事件；
  2. **反直觉的恢复顺序**：执行功能（抽象匹配、概念形成）**最早**恢复到基线，而反应速度、警觉注意、处理速度恢复更慢；
  3. 恢复意识**之前**，额顶叶皮层的动力学已先回归基线——**"舞台"先于"演员"就位**；
  4. 视觉客体学习记忆（VOLT）在 3 小时后仍有轻微残留损伤——**陈述性记忆是最后完全恢复的**；
  5. 作者给出的进化解释：睡眠使个体脆弱，苏醒时快速评估与决策能力优先。
- **睡眠与记忆巩固**（Science, 2024；CLS/TEACH 模型）：睡眠中海马体重放白天习得的模式以巩固到皮层；CA2 区介导"重置"使神经元可再次学习；睡眠中重放**优先最近激活的关联**，且重放可由皮层侧发起——支持"睡眠时间编译"与"近期使用优先固化"的设计。

### 5.2 设计映射：苏醒序列（Wake-up Sequence）

```
阶段 0  上电自检：页表完整性校验、签名验证
阶段 1  先恢复"舞台"：路由器、预测器、接口层本身
        （对应：额顶动力学先于意识恢复）
阶段 2  恢复执行功能：人格块 + 元数据块 + 核心程序性块
        （对应：执行功能最早恢复；"我是谁、我怎么思考"先于"我记得什么"）
阶段 3  恢复高频陈述性块（按 priority 与 usage_count 排序）
阶段 4  长尾惰性加载：缺页时再取（demand paging）
```

设计要点：

1. **人格块是"最小自我"**：阶段 2 完成后系统即可对外服务，尽管陈述性记忆尚未完全就位——此时应在元数据中**显式声明"记忆部分加载"状态**，避免用空白知识盲目作答；
2. **降级优雅化**：苏醒过程中能力逐步增强，类似人类苏醒时的朦胧期，系统行为应对用户透明且诚实；
3. 反直觉但重要的启示：**不要把"记住最多"当作启动目标，要先恢复"会思考、知道自己缺什么"**。

## 6. 路由与学习

### 6.1 可学习路由器，与模型共同进化

- 路由决策（何时调用、调哪块）作为**动作**，以最终任务结果为奖励用 RL 训练（PPO/GRPO）；
- 证据：Memory-R1（arXiv:2508.19828）证明监督学习无法教会记忆管理，而结果导向 RL 仅用 152 个样本即可让记忆管理策略收敛；SEAL（arXiv:2506.10943）证明"学习如何更新自己"本身可被 RL 塑造；
- 路由器与模型**共同进化**：模型 hidden state 分布随知识块注入而改变，路由器的输入分布随之漂移，需要周期性联合校准（类似 TLB 与页表的一致性维护）。

### 6.2 精确路由 + 联想路由

- **精确通道**：route_key embedding top-k 检索（PEER 式 product-key 可扩展到百万级块）；
- **联想通道**：沿 graph_links 随机游走采样 1–2 个"远亲"块，模拟跨专业迁移与类比推理（认知科学的激活扩散模型，Collins & Loftus 1975）；
- **探索率控制**：类比 ε-greedy——默认 ~10% 联想探索；头脑风暴模式调高，严谨问答模式调低；联想块注入时携带"远域类比"标记，提示模型以低置信度使用。

### 6.3 缺页语义

```
route(query) ->
  hit:  返回 {text_payload, weight_payload, confidence, version}
  miss: 异步取块（预算内） |
        超时 → { 降级策略: 次优块 | 文本RAG | 声明不可用, 记录为"空白事件" }
```

## 7. 空白检测与"回想"机制

目标行为：模型遇到知识/经验空白时不盲目猜测，而是产生"哦等等，这一块涉及我的知识空白，我应该去获取更多信息"、"让我回想一下相关的记忆"、"嗯……我需要想一想"式的内省行为。**三条信号通道按当前可靠性排序：**

1. **输出分布信号**（不改模型，立即可做）：监测生成中的 token 概率/熵，低置信触发检索——FLARE（arXiv:2305.06983）验证有效。"模型嘴上没说，但概率分布暴露了它不懂。"
2. **内部探针**（研究前沿）：轻量 probe 从中间层激活预测"模型是否真有把握"；口头校准与真实不确定性经常不一致，内部信号更诚实。
3. **显式反思 token**（最内生，需训练）：Self-RAG（arXiv:2310.11511）让模型学会输出 Retrieve/ISREL/ISSUP/ISUSE 控制 token，自主决定何时检索、检索结果是否相关、答案是否有据。

设计决策：**外部信号（1+2）做主力检测，模型自述（3）做辅助与解释层**；训练时用 1+2 收集的信号作为监督/奖励，把"承认空白→发起调用"蒸馏为模型的内生行为。元数据块（"我哪里常错"）正是这一机制的固化产物。

## 8. 记录与固化（写通道）

### 8.1 在线捕获：记录什么（按价值排序）

1. **空白事件**：低置信信号触发时的上下文 + 后续调用结果——"哪里不懂"的负样本，最直接驱动记忆增补；
2. **被用户纠正的推理**：奖励信号最强，高优先级固化；
3. **被验证正确的完整推理路径**：蒸馏为程序性 LoRA 的原料；
4. **常规思考流**：低价值，仅短期保留，LRU 淘汰。

### 8.2 睡眠时间编译

- 离线时段执行：文本经验 → 摘要/结构化 → 编译为 KV prefix / LoRA / steering vector → 注册进页表；
- 证据：Sleep-time Compute（arXiv:2504.13171）证明离线预消化上下文可降 5 倍测试时开销；睡眠记忆巩固研究支持"优先重放近期激活内容"；
- 类比编译器：源代码（markdown）是 ground truth，编译产物可失效、可重建。

### 8.3 冲突仲裁

- 新块与旧块矛盾时：版本号 + 时间戳 + 置信度三路仲裁，CONTRADICTS 边显式连接；推理时由路由器按情境选择，默认新且高置信者优先，冲突未决时**保留两者并标注分歧**（而非静默覆盖）。

### 8.4 安全：可写记忆的攻击面

- 2026 年的智能体记忆安全综述（arXiv:2604.16548）指出：记忆生命周期六阶段（写-存-取-执行-共享-遗忘）中，**存储与遗忘/回滚是研究最稀薄的环节**；投毒内容被反思/摘要吸收后会被"晋升"为更高优先级的教训；
- 本设计的对策：块签名、写入权限分级（人格块 > 元数据块 > 知识块）、源代码形态可审计可回滚、编译产物可随时废弃重建。

## 9. 接口规范草案（ABI v0.1）

```
请求 Request {
  query_vec:      当前 hidden state / 显式反思 query
  intent:         RECALL_FACT | RECALL_SKILL | CHECK_BLANK | ASSOCIATE
  budget:         { max_latency_ms, max_blocks }
  context_digest: 当前思考段摘要（供二级路由）
}

响应 Response {
  text_payload:   [ { block_id, text, confidence } ]      ← 给"嘴"
  weight_payload: [ { block_id, kind, payload_ref, ttl } ] ← 给"脑"
  status:         HIT | PARTIAL | MISS_DEGRADED | BLANK_DECLARED
  trace:          路由决策记录（供训练与审计）
}

权重注入语义（三选一，按块类型）：
  - KV prefix 注入：立即生效于下一 token
  - steering vector：加在指定层残差流，立即生效，效果粗
  - LoRA delta 热挂载：对注入点之后的所有 token 生效，秩8约数MB，PCIe ~1ms 级
```

双通道语义：**文本通道回答"这次思考需要什么内容"，权重通道回答"接下来该怎么思考"**——对应陈述性记忆与程序性记忆的分离。

## 10. 人格块：对智能体的深度集成

### 10.1 证据

Persona Vectors（Anthropic, arXiv:2507.21509）证明：人格特质（如谄媚、幻觉倾向、"邪恶"）在模型激活空间中对应**可提取的线性方向**，可用于：(1) 部署时监测人格波动；(2) 推理时 steering 抑制不良转变；(3) 微调时预防性 steering 阻止人格漂移；(4) 预测哪些训练数据会导致人格变化。

### 10.2 设计

- **人格块 = persona vector 组 + 人格摘要文本 + 行为边界规则**；常驻 L0，冷启动阶段 2 第一批加载（§5）；
- 与知识块的差异：更新更慢、写入需更高权限、修改需显式审计——人格是"固件"不是"数据"；
- 人格块也参与路由：相同问题在不同人格设定下应路由到不同程序性块（例如"严谨工程师人格"优先调用保守推理习惯的 LoRA）。

## 12. 开放问题

1. **转译保真度**：KV 压缩对精确数字/代码不友好——"何时回退读源代码"的判断逻辑待设计；
2. **块边界**：知识块的切分粒度（事件/主题/动态合并分裂）——类似页大小之争，无先验最优；
3. **路由器-模型共漂移**：共同进化如何避免振荡与共谋（router 只选让模型"舒服"的块）；
4. **归因评估**：插入知识块后如何验证它被真正"用上"而非干扰——文献空白，需自研实验；
5. **冲突仲裁的推理时语义**：保留冲突双方时，模型如何表达"我记得两个矛盾版本"；
6. **人格块的可编辑边界**：哪些人格维度允许在线演化、哪些必须锁定——涉及安全与身份认同；**EXP-PERSONA 即该问题的实验载体（MCB 闸门 + 分级写通道，见实施计划 §8A）**；
7. **多智能体共享**：知识块能否跨模型实例迁移（不同底座间"编译产物"大概率不可移植，只能共享源代码）。

## 14. 双向接口与自我进化闭环（v0.2 新增）

### 14.1 从"可回忆"到"可进化"

单向接口（只读）实现的是"能查资料的员工"；双向接口（读+写）才实现"会积累经验的员工"。目标闭环：

```
思考 → 检测空白/捕获经验（写信号）→ 记入日志区 → 睡眠固化 → 页表更新
  ↑                                                              │
  └──────── 后续思考经路由读回知识块（读信号）←────────────────────┘
```

### 14.2 写通道的三类证据

1. **SRWM（ICML 2022, arXiv:2202.05780）**：权重矩阵在运行时持续修改自身的全部权重——网络自生成 key/value/临时学习率，经外积与 delta 规则自我重编程。证明"模型自己控制写"在原理上可行；但论文明确警告：长期无法保证自修改保持原始目标函数（内对齐风险），这是权限设计（§14.4）的直接动机。
2. **Fast Weight Programmers（ICML 2021）**：线性注意力的写入=key-value 外积累加、检索=矩阵-向量乘。"写记忆"早已内置于每一层，双向接口是把隐式操作显式化、可寻址化、持久化。
3. **LaCT / TTT-E2E（2025）**：推理时梯度更新快权重可扩展到模型参数 40% 的状态规模，可接入 Muon 优化器在线更新——"推理中写权重"的算力障碍已消除。

### 14.3 写原语分级（按修改深度）

| 级别 | 操作 | 何时允许 | 风险 |
|---|---|---|---|
| W0 | 日志追加（文本+激活快照，只增不改） | 运行时总是允许 | 无 |
| W1 | steering vector 捕获/注入 | 运行时允许（可逆） | 低 |
| W2 | KV prefix 追加（编译产物） | 运行时允许 | 低-中 |
| W3 | LoRA delta 梯度更新 | 仅离线 | 中 |
| W4 | 合并固化入主干 | 仅离线+审计 | 高 |

**核心设计决策：双向 ≠ 对称。读是同步的（思考途中），写是异步的**——运行时只允许 W0–W2 且绝不触碰正在运行的权重（类比 WAL：write() 返回不等于 fsync 完成）；W3 以上在"睡眠时间"执行（类比 fsck + merge）；固化期间读通道看到旧版本快照（copy-on-write / MVCC）。

### 14.4 页保护位（写权限分级）

类比 OS 内存保护：**人格块运行时只读（W^X 的代码段），元数据块写入需验证门，知识块可写，draft 日志区=用户态缓冲区**。模型可自由学习"知识"，但不能在运行时重写"我是谁"；人格演化走离线高权限审计通道。

> **v0.4 修订注记（EXP-PERSONA 沙箱例外）**：经用户决策，新增极其实验性目标 EXP-PERSONA——在"KAL 道德约束块（MCB）"作为强制闸门的前提下，分级探索人格块写能力（E1 离线写 → E2 运行时受限 α 调制 → E3 运行时微写，默认停在 E1）。**本节红线在实验沙箱外维持原状**；MCB 自身保护等级高于人格块（永不可写），苏醒序列中先于人格块加载。完整实验规范、退出标准与失败回退见《从零构建TAIS-Obsidian_总体实施计划.md》§8A。

### 14.5 闭环风险与对策

1. **信用分配**："哪一刻值得记"无监督信号 → 结果奖励 RL（Memory-R1/SEAL 路径）；
2. **自我强化偏差**：读影响写、写影响读，路由器可能只记"让模型舒服"的块 → 定期外部评测集"记忆体检"；
3. **写放大与投毒**：draft→固化之间必须有验证门 + 签名 + 可回滚（源代码形态是最后的审计依据）。

## 15. probe 集成路径与实验底座决策（v0.3 新增）

### 15.1 集成深度三步走

用户的明确决策：验证阶段用**外部 probe** 插入模型内部捕获信号（不改模型），初步评估后再做深度集成。对应三阶段：

1. **外挂感知**（probe 只读）：hook 捕获 hidden state / 输出分布，训练空白检测器，不改模型任何行为；
2. **外挂干预**（probe + 注入）：检测空白→触发回想→注入知识块（LoRA/KV/文本），模型行为被外部回路改变；
3. **架构内生**：接口 token 化、页表可微化（见 §15.4 远期规划）。

### 15.2 空白检测的 probe 证据

SAPLMA（Azaria & Mitchell, EMNLP 2023 Findings, arXiv:2304.13734）：在模型阅读/生成语句时取 hidden state，训练逐层线性分类器即可判定真假，平均准确率 71–83%，**显著优于直接读 token 概率**（后者受句长和词频污染）；最强信号在**中间层**（GPT-3 约第 20 层）。后续工作（EigenScore、MIND、"LLM Internal States Reveal Hallucination Risk", arXiv:2407.03282）进一步确认内部状态可暴露幻觉风险。结论：**probe 方案是整个系统里证据最扎实的一环**，可作为第一个实验。

### 15.3 实验底座：Qwen3.5 小模型评估

**结论：推荐，主力用 Qwen3.5-9B，管线调试用 4B，备选基线 Qwen3-8B（全注意力）。**

事实核查（2026.02 发布）：Qwen3.5 家族含 0.8B / 2B / 4B / 9B（dense）、27B（dense）、35B-A3B / 122B-A10B / 397B-A17B（MoE）；全系 **Gated DeltaNet : Gated 全注意力 = 3:1 混合架构**，原生 262K 上下文（可扩 ~1M），原生多模态，MTP 训练。

优势：
- 小尺寸开源权重齐全，单卡可迭代；中文能力强（对中文经验记录友好）；
- **混合架构是加分项而非障碍**：GDN 层的固定大小递归状态本身就是"快记忆"基板，与未来架构内生路线（§15.4）方向一致；
- vLLM 已支持运行时动态加载 LoRA（`/v1/load_lora_adapter`），知识块热插拔有现成工程基础。

注意事项（已写入 Block Spec 约束）：
- **GDN 层无 KV cache**（只维护 ~32KB/头的固定状态矩阵）→ KV prefix 注入只适用于 25% 的全注意力层；LoRA 注入两层通用。知识块的"载体适用性"必须按层类型标注；
- GDN 层的 LoRA/探针工具链比全注意力层新，需预留适配工作量；
- 多模态权重与纯文本实验无关，可冻结 vision tower；
- 对照组建议保留一个全注意力模型（Qwen3-8B），用于分离"混合架构效应"与"记忆系统效应"。

### 15.4 远期：统一先进架构（DKB-native）规划

- **中期**：接口 token 内化——训练模型自主发出路由调用（Self-RAG/Memory-R1 路径），页表条目作为特殊控制 token；GDN 递归状态暴露为可读写的"工作记忆寄存器"；
- **远期**：页表进模型（可微地址转换层）、多时间尺度记忆（CMS 式，不同频率的固化通道）、受控自修改子层（SRWM 思想 + 权限沙箱）、路由预测器/预取器硬件化（可部署到 FPGA/边缘侧做确定性低延迟预取，与嵌入式容器平台协同）；
- **评估体系同步建设**：记忆归因、空白识别率、固化保真度、苏醒时间——文献均无现成基准，需自研。
